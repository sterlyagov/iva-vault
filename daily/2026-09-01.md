## Где встраивать TTS

Основной интерактивный путь ответа:

1. `agent/channels/telegram.ts`
   - обработчик события `events["message.completed"]` — финальная реплика модели;
   - сейчас вызывает:
     ```ts
     traceOutbox(..., () =>
       sendThroughOutbox(message, outboxTransport(channel.telegram))
     )
     ```
   - `finishReason === "tool-calls"` и пустые сообщения уже отсекаются.
2. `agent/lib/outbox.ts`
   - `sendThroughOutbox()` — обязательный единый outbound-шов:
     - `redactNotice()` / outbound security gate;
     - rich → HTML → plain fallback;
     - подсчёт `delivered`, `ok`, `error`.
3. `outboxTransport()` в `agent/channels/telegram.ts`
   - фактические вызовы Bot API через `TelegramHandle.request/post`;
   - `request(method, body)` допускает произвольный Bot API метод, поэтому `sendVoice` технически доступен.

Cron/дайджесты идут отдельно через `scripts/lib/telegram-send.ts → sendThroughOutbox()`. Их лучше **не озвучивать**, если требование относится именно к ответам в чате.

## Рекомендуемая архитектура

Создать отдельный модуль, например:

- `agent/lib/openai-tts.ts`
  - `readTtsConfig(env = process.env)`;
  - `synthesizeSpeech(text, config, { fetchImpl = fetch })`;
  - POST `https://api.openai.com/v1/audio/speech`;
  - возвращать `ArrayBuffer`/`Blob`, без временных файлов.

- `agent/lib/telegram-voice-response.ts`
  - принимает уже прошедший outbound-gate текст, Telegram handle и injectable TTS-функцию;
  - отправляет `sendVoice` через `multipart/form-data` либо отдельный прямой Bot API fetch.
  - Важно: текущий `TelegramHandle.request()` рассчитан на JSON. Бинарный voice нельзя безопасно положить в его `JsonObject`; значит:
    - либо расширять Eve/API транспорт;
    - либо локально делать multipart POST на
      `https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendVoice`.
  - Передавать `chat_id` и при наличии `message_thread_id`.

Лучший шов — добавить в `OutboxTransport` необязательный метод, например `sendVoice?(text: string)`, и вызывать его **после `const text = redactNotice(message)`**. Так TTS никогда не получит исходный секрет. Не синтезировать напрямую из `data.message` до Outbox.

Политику доставки стоит определить явно:

- безопасный дефолт: текст остаётся канонической доставкой, voice — best-effort дополнение;
- ошибка OpenAI/Telegram voice не должна превращать успешно доставленный текст в `result.ok=false`;
- пустой текст и `tool-calls` не озвучивать;
- в группах желательно выключить по умолчанию либо ограничить private chat через `channel.telegram.chatType`;
- ввести лимит длины/символов до запроса TTS.

Если нужен режим «voice вместо текста», придётся аккуратно пересмотреть:
- `OutboxResult.delivered`;
- `emitTelegramTurnLatency()` в `message.completed`;
- trace-событие доставки;
- fallback на текст при сбое TTS.

## Конфигурация

Конвенция проекта — верхнерегистровые значения в `.env`, читаемые через `process.env`; изменения применяются после перезапуска процесса.

Предлагаемые opt-in переменные:

```dotenv
OPENAI_API_KEY=
TELEGRAM_TTS_ENABLED=false
TELEGRAM_TTS_MODEL=gpt-4o-mini-tts
TELEGRAM_TTS_VOICE=alloy
TELEGRAM_TTS_FORMAT=opus
TELEGRAM_TTS_MAX_CHARS=4000
```

`opus` подходит для Telegram voice note лучше MP3. Если OpenAI endpoint/модель возвращает иной контейнер, проверить совместимость `sendVoice`.

Точные места конфигурации:

- `.env.example` — документировать optional-блок рядом с Telegram/Deepgram.
- `scripts/setup/main.ts`
  - `writeEnv()` и его стабильный массив `order` — добавить новые ключи, иначе неизвестные ключи всё равно сохранятся, но окажутся в хвосте;
  - если TTS должен настраиваться через `iva config`, добавить opt-in вопросы после Deepgram или Telegram;
  - **не** добавлять `OPENAI_API_KEY` в `REQUIRED`, иначе optional-функция сделает всю установку «неполной»;
